# 托管网站直连本地 CLI

日期：2026-11-19

## 目的

别人打开托管的网站，运行一条命令连上自己的电脑，之后直接在网站上安装、删除 skill 和插件，不需要再做别的。

## 用户流程

1. 打开托管网站。页面是演示模式，最上面有“连接你的电脑”：一条命令 `npx ai-skills-installer ui` 和复制按钮。
2. 在终端运行这条命令。浏览器自动打开托管网站，地址后面带 `#connect=端口.令牌`。
3. 页面读到连接信息，切换成真实模式，所有操作发到 `http://127.0.0.1:端口`。终端窗口要一直开着。
4. 连不上时（浏览器拦截，或终端已关），页面显示提示和“打开本地页面”按钮，本地页面和以前一样可用。

## 目标与非目标

- 目标：运行一条命令后，托管网站能做本地页面能做的全部操作。
- 非目标：不做后台常驻服务，不做免命令的浏览器直写文件夹，不做账号或登录。
- 不能发生：别的网站能驱动用户的本地服务；页面绕过 CLI 的安全规则。

## 考虑过的做法

1. **托管网站直连本地 CLI（选定）**：用户只运行一条命令，功能完整。代价是 Chrome 会问一次是否允许访问本地网络，Safari 可能拦截，所以保留本地页面作后备。
2. 网站只显示可复制的命令：最简单，但网站看不到已安装的内容，每装一个都要回终端，不算“连接”。
3. 浏览器直接写文件夹：不用命令，但只有 Chrome 和 Edge 支持，用户要手动选每个工具的文件夹，装不了插件。

## 设计

- **`src/ui.mjs`**
  - `SITE`：要打开的托管网站，默认 `https://catflyx520.github.io/skill-installer/`（随本仓库自动部署），可用环境变量 `SKILL_INSTALLER_SITE` 改。
  - 允许的来源：`SITE` 的来源、`https://catfly.dev`、`https://catflyx520.github.io`，以及本地页面自己。
  - `/api/*`：带 `Origin` 且不在允许列表里的请求一律 403；允许的来源得到 CORS 头。`OPTIONS` 预检在令牌检查之前回答，并带 `Access-Control-Allow-Private-Network: true`。
  - 令牌检查、参数校验、写操作排队都不变。本地页面的 CSP 不变。
  - 启动时打开 `SITE#connect=端口.令牌`，同时打印本地地址作后备。
- **`ui/app.js`**
  - 启动时读 `#connect=端口.令牌`，存进 `sessionStorage`（刷新后还连着），再把它从地址栏去掉。
  - 有连接信息时把页面设成 `data-mode="local"`，请求发到本地地址。
  - 连接失败时的提示带“打开本地页面”按钮。
  - 复制命令的按钮。
- **`ui/index.html`、`ui/i18n.js`、`ui/style.css`**：演示模式下的“连接你的电脑”卡片，中英文文案。
- **测试（`test/ui.test.mjs`）**：允许的来源能通过预检并拿到 CORS 头；别的来源即使带着正确的令牌也是 403；启动输出里有连接地址。

## 我做的决定（没有和用户逐条确认）

- 默认打开 GitHub Pages 而不是 catfly.dev：后者是固定版本，新页面要等 Portfolio 重新发布才生效。之后改一个常量即可切换。
- 令牌放在 `#` 后面：不会发给网站服务器，也不会出现在 Referer 里。
- 不加 `--local` 之类的新参数：后备的本地地址已经打印出来，页面上也有按钮。

## 发布顺序

先推送页面（GitHub Pages 自动部署），再发 npm 新版本。反过来的话，新 CLI 会打开还不认识连接信息的旧页面。
